### 2.1 Development pilot (val_seen-300, fixed subset; not a test result)

Does moving M5's retention from token-level (per-layer top-B rows) to the frame-level decision unit that
MemFork learns over cost accuracy before any RL? `m5_e1_frame_prior` = M5_E1 weights + a
`memory_retention.pt` that keeps the running top-F frames by the frame-mean committed-write score
(`scripts/rl/make_frame_prior_checkpoint.py`).

| M5_E1 retention | SR | SPL | NE | OSR | TL | failures |
|---|---:|---:|---:|---:|---:|---:|
| native (token-level, per layer) | 49.33 | 45.97 | 5.42 | 61.67 | 9.96 | 0 |
| frame-level prior (greedy) | 48.67 | 45.55 | 5.79 | 61.33 | 9.95 | 0 |

Paired over the 300 episodes: ΔSR −0.67 (95 % bootstrap CI [−5.3, +4.0]), ΔSPL −0.42 ([−4.6, +3.5]),
26 gained / 28 lost, McNemar p = 0.89. The frame-level decision unit costs no detectable accuracy at
initialization (power is limited: n = 300), so MemFork starts from a policy equivalent to M5_E1 and any
RL difference is attributable to training, not to the reparameterised memory.

GRPO on M5_E1 raises SR significantly, but SPL only by a non-significant +1.7: trajectories get longer
(TL 9.50 → 11.04 m, 95 → 109 actions, forced stops 142 → 174) and "passed within 3 m, then stopped
outside" grows from 124 to 175 episodes while "never within 3 m" falls from 547 to 417. RL makes M5 explore
further and reach the goal more often (OSR +7.7) but leaves stopping/efficiency credit largely unsolved —
the failure mode F-B's stop-boundary credit and MemFork's memory credit target. (Window8 for reference:
GRPO s1 over SFT, `hico_po_report.md`.)

**GRPO+F-B on M5_E1.** Fork credit fixes exactly that failure: vs GRPO, "passed within 3 m, then stopped
outside" falls 175 → 86 and paths shorten back to M5_E1's length (TL 11.04 → 9.63 m, 109 → 97 actions,
forced stops 174 → 136) while OSR stays (−0.8), so SPL gains more than SR (+5.21 vs +4.35, both
p < 1e-3). Unlike Window8, where GRPO+F-B over GRPO was n.s. at G = 4 (`hico_po_report.md`), on M5 the
gap is significant on one seed. It uses 2.1× the simulator steps and 1.6× the policy forward steps of
GRPO, so whether it is interaction-efficient is decided by the M5 G = 8 control (pending), not by this row.

## 4. Memory behaviour

### 4.1 MemFork training records (`scripts/rl/analyze_memfork.py`, `results/m5/memfork_memory_behaviour.json`)

Main trajectories of both ranks, per block of 25 RL steps (~48 k memory decisions per block). This is
training-time behaviour, not an evaluation; the greedy-retention val_unseen result is in §3.

| steps | decision entropy | agrees with M5 frame prior | drops the new candidate | drops the oldest | kept-frame age | memory fork re-drew a different m_t | |R_main − R_branch| differs / same | success flip differs / same |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 0–24 | 1.33 | 0.35 | 0.33 | 0.11 | 12.2 | 0.75 | 2.70 / 3.08 | 0.16 / 0.19 |
| 25–49 | 0.82 | 0.34 | 0.56 | 0.06 | 21.7 | 0.62 | 2.54 / 2.52 | 0.18 / 0.15 |
| 50–74 | 0.61 | 0.46 | 0.68 | 0.03 | 25.9 | 0.51 | 2.89 / 2.25 | 0.15 / 0.16 |
| 75–99 | 0.66 | 0.60 | 0.64 | 0.03 | 26.4 | 0.58 | 2.68 / 2.33 | 0.17 / 0.14 |
| 100–124 | 0.21 | 0.87 | 0.86 | 0.02 | 36.2 | 0.20 | 1.96 / 2.48 | 0.14 / 0.15 |

(Entropy of a uniform choice over the 5-frame pool is ln 5 = 1.61; ages in decision steps.)

Reading, stated as observed:
- Retention first spreads out (near-uniform early), then **collapses back onto the M5 prior**: by the
  last block 87 % of sampled drops equal the frame-level GDN prior's choice and 86 % reject the newly
  expiring candidate, so long-lived frames are kept (kept-frame age 12 → 36 steps). RL rediscovered
  M5's own "keep old evidence, reject the new frame" rule rather than finding a different policy.
- **Memory-fork credit fades with the entropy**: in the last block only 20 % of memory forks re-draw a
  different m_t, so most memory forks carry no contrast for φ.
- **No measurable causal effect of the re-drawn memory on return at the fork**: sibling return gaps and
  success flips are not larger when the branch's memory differs than when it is identical (e.g. last
  block 1.96 vs 2.48, 0.14 vs 0.15). Branch outcomes vary through action sampling either way.
These are a warning for the memory-credit hypothesis: whatever MemFork gains over GRPO+F-B on val_unseen
must be checked against A1 (frame-greedy memory + F-B), which isolates learned retention.
